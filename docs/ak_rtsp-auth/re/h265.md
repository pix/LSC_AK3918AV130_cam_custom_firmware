# H.265 on the AK3918AV130: not available (driver-gated)

Tried 2026-11-13, dropped. The code that was tested is kept in `h265_probe.patch`
(video.codec setting, HEVC profile word, crash marker, RTSP H.265 via SmolRTSP).

## What the encoder stack is
`ak_venc_adapter.ko` wraps Allegro DVT's encoder library (the same IP and API as the
open-source Xilinx VCU control software, `Xilinx/vcu-ctrl-sw`). Profile words follow
`lib_common/Profiles.h`: `codec << 24 | flags << 8 | profile_idc`, codec 0 = AVC,
1 = HEVC, 4 = JPEG. So H.264 Main = 77, High = 100, AVC Constrained Baseline =
0x242 (66 | 2 << 8, not "Constrained High"), HEVC Main = 0x1000001.

## What works on the driver side
- `AKV_Encoder_Open_Ext` / `ExtParamToUserParam` pass the profile word straight
  through; the codec is taken from its top byte.
- `AKV_Encoder_Get_Dma_Memory_Info` has an HEVC branch (32x32 CTB). On the camera,
  QUERY_DMA with 0x1000001 returned 9 blocks, 5 026 272 bytes (H.264: 8 blocks,
  4 120 384), and the pools were allocated without error.
- SDK `ak_venc.h`: `PROFILE_HEVC_MAIN` (profile 4), shared level numbering
  (`HEVC_AVC_LEVEL_1 = 10`), `rc.cub_size` 0 = 32x32 CU (HEVC only).

## Why it stops
CREATE_ENC fails cleanly (no crash): kernel log `## HEVC profile is not supported!!`
then `venc_create_chn: AKV_Encoder_Open failed`.

- `AkvEncOpen` -> `FUN_00021e50(param, user, caps)` with `caps = dev+0x1658`:
  0/3 = both codecs, 1 = HEVC only ("AVC profile is not supported"),
  2 = AVC only ("HEVC profile is not supported").
- `caps` is written only in `AL_SchedulerCpu_Create`, from an IP-controller
  `ReadRegister(0x2140000C)` (encoder MMIO block, a signature word):
  `0x3FA3D9E7` -> caps 2 (AVC only), continue;
  `0xE2BF9BBC` -> caps 1, then the scheduler is freed (fail);
  `0x2FB246AF` or anything else -> fail.
  There is no path to caps 0: this driver build only runs AVC.
- Whether the silicon has a working HEVC core is unknown: Anyka documents
  H.265/H.264 for the AK3918AV100 family, nothing official for the AV130, and no
  public test results (OpenIPC ships the AV130 encoder as the prebuilt vendor
  module). Forcing caps 0 would mean patching and reloading the kernel module, with
  a real risk of hanging the encoder IP; not attempted.

## Pitfall found on the way
Module settings are replayed *before* the encoder is created
(`[control] restored N module settings` precedes `venc`), so a setter that clears a
crash marker runs at every boot. Seed such state from `control_saved_get` and only
clear markers on a change made after startup.
